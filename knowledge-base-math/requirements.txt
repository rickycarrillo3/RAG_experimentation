# Pinned so a fresh install on the pod reproduces a known-good environment. Unpinned,
# two installs a month apart resolve differently — the class of bug that makes "works
# on the Mac, breaks on the pod" expensive to chase, and that silently invalidates any
# eval parity run, since evaluation/EVALUATION.md §7 only means something against a
# known stack.
#
# Captured 2026-08-15 from the working venv, with gradio moved to 5.x (see below).
# Verified to resolve clean-room: pip install --dry-run --ignore-installed -r this file.
#
# ── Why gradio is 5.x and not 6.x ─────────────────────────────────────────────
# These three constraints have no common solution:
#     marker-pdf 1.10.2  →  transformers <5.0.0
#     transformers 4.x   →  huggingface-hub <1.0
#     gradio 6.x         →  huggingface-hub >=1.2.0
# The venv this was captured from had gradio 6.18.0 against huggingface-hub 0.36.2,
# which `pip check` flags — it worked only because it was built incrementally into a
# state pip's resolver will not reproduce. Something had to give, and it is gradio:
# holding the ML stack still keeps extraction and retrieval behaviour identical, so
# the recorded eval numbers stay comparable. Moving marker-pdf to 2.0 instead would
# have bumped transformers to 5.x and surya to 0.22, changing the extraction engine —
# which shifts chunk boundaries and breaks every gold label (see CLAUDE.md).
#
# The cost is one line in app.py: gr.Chatbot needs type="messages" on Gradio 5, where
# the default is still the legacy tuple format and dict messages are rejected outright.
# Note this couples app.py to the pin in one direction — Gradio 6 REMOVED the `type`
# parameter rather than redefaulting it, so that line raises TypeError on 6.x. Raising
# the gradio pin back to 6 means deleting the argument in the same commit.
#
# torch is pinned by version, not build: the version is platform-independent and pip
# picks the CUDA wheel on Linux, CPU/MPS on macOS. If a pod image resolves a CPU-only
# build, reinstall from the CUDA index — see SETUP.md §1.
